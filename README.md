# VideoML CLI: local voiceover

`vml init` creates `.videoml/config.yml` for a new project with Auritus, `kokoro:af_heart`, speed 1 and seed 0. It refuses to overwrite a configuration. Existing projects retain their explicit provider; narration without a provider requires an explicit `tts.default_provider`, `voiceover.provider`, or `--provider`. CI does not silently select dry-run. Use `--provider dry-run` explicitly for simulated output.

Install the Auritus CLI and Kokoro dependencies in the Python environment selected by `providers.auritus.python`, following Auritus's installation instructions. Kokoro model and voice files, backend packages, hardware and licenses are separate dependencies; consult their upstream terms and requirements. `vml speech-setup --python /path/to/python` explicitly downloads only Kokoro configuration and weights and the selected voice file using the installed Hugging Face client. Apple Silicon uses the separate voice repository. The command prints local immutable snapshot paths, accepts `--voice kokoro:af_heart`, and honors the configured Python unless `--python` overrides it. This can require substantial disk space and network access. `vml speech-diagnostics --python /path/to/python` reports local readiness without downloading; readiness is not proof of successful inference. Generation itself never downloads a model. Test stubs do not replace a real Kokoro smoke run.
